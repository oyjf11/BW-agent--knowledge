# 7.4 工具封装

> 所属分支：[[07-工具与集成层/_index|07-工具与集成层]]

## 子节点 / 待填充要点
- Skill 自动触发机制
- Meta-skill 设计
- Skill 注册与发现
- Skill 组合与编排

## 一句话定义

Skill（技能）是对高频任务的工程方法论封装——不是一次性 prompt，而是可复用、可组合、可自我改进的任务级方法论单元，agent 通过自动检索和匹配机制在任务启动时加载执行。

## 解决什么问题

传统 Prompt Engineering 的痛点：
- 每次任务都要用户写提示词提醒模型遵守规范
- 模型不一定稳定遵守
- 不同 session 执行风格不一致
- 经验无法沉淀复用

Skill 机制解决：**不是让用户记住流程，而是让 agent 自己记住流程。**

## 如何实现

### Skill 自动触发机制

通过 session hook / bootstrap prompt 注入三条核心规则：

1. 你有 skills（可用技能清单）
2. 你要搜索 skills（按任务匹配）
3. 如果有适用 skill，必须使用它（强制执行）

```text
任务进入
  → Router 判断任务类型
  → Skill Registry 检索匹配 skill
  → 加载 skill 内容到上下文
  → Agent 按 skill 定义的流程执行
  → 执行结果回写，更新 skill 效果指标
```

### Meta-skill 设计

Meta-skill（元技能）是"如何创建和使用技能"的技能，形成自举循环：

```text
当你开始任务时，先判断有没有适合的 skill
  → 如果有，必须读取并使用
  → 如果没有，可以创建或改进 skill
```

这等价于一个 skill 选择路由器：

```text
Router → Skill Selection → Agent Execution
```

### Skill 的组合与编排

Skills 不是孤立使用的，可以组合形成更复杂的工作流：

```text
复杂需求
  → brainstorming skill（澄清目标）
  → writing-plans skill（制定计划）
  → executing-plans skill（执行任务）
  → test-driven-development skill（TDD 验证）
  → verification-before-completion skill（完成前验证）
  → requesting-code-review skill（代码审查）
```

### Skill 的可扩展设计

```text
Skill 可以被新增（从新经验中创建）
Skill 可以被修改（优化流程）
Skill 可以组合（编排多 skill 工作流）
Skill 可以沉淀新的工作流（self-improving）
```

对应的知识沉淀循环：

```text
Bad Case → 归因 → 规则/Skill/Planner Prompt 更新 → 下一次复用
```

## 项目映射

- AI Coding 工具包：Commands（用户入口）→ Agents（执行角色）→ Skills（方法单元）→ Rules（边界约束）
- 应用生成平台：Router 可作为 skill selector，每个 Planner 可作为独立 skill 调用
- 运维智能体：每种故障类型对应一个排查 skill（如 `k8s_pod_crashloop_skill`）

## 高频追问

1. **Skill 和 Prompt 有什么区别？**
   → Prompt 是一次性提示，每次任务都要重新写。Skill 是任务级方法论封装，一次创建、多次复用，且可以组合和演化。

2. **Skill 和 AGENTS.md 有什么区别？**
   → AGENTS.md 是项目级静态规则（"这个项目里要用 TypeScript"），Skill 是任务级可组合方法论（"当你需要调试时，按这个流程做"）。Skills 可选择、可组合、可自我改进。

3. **怎么防止 skill 冲突或误触发？**
   → 需要 skill 准入机制、触发条件匹配规则、冲突仲裁逻辑和 skill 质量评估。

4. **Meta-skill 会不会导致模型自己创建低质量 skill？**
   → 会的。所以需要 skill review/critic 环节和效果评估机制。写作 skill 本质是高风险操作，需要约束。

## 我的回答要点

> Skill 不是简单的一次性 prompt，而是把工程经验沉淀为可调用、可组合的方法论资产。我们通过 session 启动注入和 skill 自动检索机制，让 agent 在任务启动时先判断有没有合适 skill，有则必须加载执行，没有则可以创建。这样做的目标是让 AI Coding 从"每次靠模型临场发挥"变成"每次按稳定流程执行"，降低随机性、提升一致性，并形成可复用的工程能力库。
