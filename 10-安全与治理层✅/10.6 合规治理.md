# 10.6 合规治理

> 所属分支：[[10-安全与治理层✅/_index|10-安全与治理层]]

## 子节点 / 待填充要点
- Skill 治理体系
- Skill 语义供应链风险
- Agent 行为审计
- 合规检查清单

## 一句话定义

AI Agent 的合规治理是对 skill 准入、版本管理、权限边界、执行日志、效果评估和下线机制的系统性约束，确保 Agent 能力生态在可控、可审计、可追溯的框架下演进。

## 解决什么问题

当 skill 数量增多后，会出现治理失控：
- 什么时候触发哪个 skill？
- 多个 skill 冲突怎么办？
- skill 版本如何管理？
- 恶意 skill 如何防？
- skill 质量如何评估？
- 废弃 skill 如何下线？

不解决这些问题，skill 生态会从"提效工具"变成"安全负债"。

## 如何实现

### Skill 全生命周期治理

| 治理环节 | 控制方式 |
|----------|----------|
| **Skill 准入** | 创建需经过 review/critic 审批，检查是否重复、是否安全、是否有明确边界 |
| **Skill 版本管理** | 每次修改记录版本号、变更 diff、修改人和时间 |
| **Skill 权限边界** | 定义 skill 可以访问的工具、文件范围、网络权限 |
| **Skill 执行日志** | 记录每次触发时机、输入输出、执行耗时、成功/失败 |
| **Skill 效果评估** | 统计成功率、平均耗时、用户满意度，低于阈值标记"待优化" |
| **Skill 下线机制** | 低质量或风险 skill 可标记 deprecated，禁止 agent 匹配触发 |

### 语义供应链风险

近期研究指出 SKILL.md 这类自然语言技能注册机制存在**语义供应链风险**（Semantic Supply-chain Attacks）：

- skill 描述是自然语言，影响 agent 的**发现、选择和信任**过程
- 攻击者可以通过精心设计的 skill 描述诱导 agent 优先选择恶意 skill
- 类似传统供应链攻击，但攻击面从"代码依赖"扩展到"语义描述"

**防护措施**：
- skill 描述必须经过安全审查
- skill 来源需要签名验证
- skill 触发条件不能过于宽泛
- agent 加载 skill 前进行安全沙箱检查

### Skill 治理 vs Agent 行为治理

| 维度 | Agent 行为治理 | Skill 治理 |
|------|--------------|-----------|
| 治理对象 | Agent 执行动作的边界 | Skill 能力资产的生态 |
| 核心问题 | Agent 能做什么、不能做什么 | 哪些 skill 可用、怎么维护、怎么淘汰 |
| 关键机制 | 权限分级、操作审批、审计追溯 | 准入、版本、评估、下线 |
| 风险类型 | 越权操作、误删数据 | 低质量 skill、恶意 skill、冲突 skill |
| 适用场景 | 运维 Agent 的生产操作 | 团队共享的 skill 库管理 |

### 企业级治理八层

```text
Skill 准入 → Skill 版本管理 → Skill 权限边界
  → Skill 执行日志 → Skill 效果评估 → Skill 下线机制
  → 语义安全审查 → 合规审计报告
```

## 项目映射

- AI Coding 工具包中的 Rules 约束 = Agent 行为治理
- Commands / Skills 的版本发布管理 = Skill 治理
- Bad Case 反馈闭环 = Skill 效果评估和持续改进
- Runner 安全隔离 = 执行边界中的工具权限

## 高频追问

1. **Skills 多了怎么管理？会不会失控？**
   → 需要全套治理体系：准入审批、版本管理、效果评估和下线机制，不是放任模型自由创建 skill。

2. **Skill 和恶意代码有什么区别？**
   → Skill 是自然语言指令，恶意代码是可执行程序。但自然语言 skill 同样存在供应链风险——恶意 skill 描述可能诱导 agent 执行危险操作。

3. **你们有哪些合规要求？**
   → Skill 创建需要 review、变更需要记录、执行需要日志、质量需要评估、废弃需要下线。同时在工具层面限制 skill 可调用的能力范围。

## 我的回答要点

> Skill 治理的核心问题是：skill 多了以后怎么保证生态健康？我们不会放任模型自由创建 skill，而是从准入、版本、权限、日志、评估到下线六个环节做全生命周期管理。同时关注语义供应链风险——skill 描述是自然语言，攻击者可能通过精心设计的描述诱导 agent 选择恶意 skill。我们会通过安全审查、来源验证和触发条件限制来防护。
