# 13.10 高级面试追问点

> 所属分支：[[13-Agent Runtime深水区✅/_index|13-Agent Runtime深水区]]

## 一句话定义

Agent 面试深入追问的本质不是在考一个名词，而是在考察你是否理解 Agent 从 Demo 走向生产系统时需要哪些工程化机制，以及你是否能按难度层级递进回答。

## 解决什么问题

求职者常见迷茫：
- 知道 checkpoint 解决什么问题，但不知道怎么实现的 → 只能做初级回答
- 不知道面试官问题的切入角度和考察意图 → 容易被追问逼到墙角
- 面试题零散记忆，缺乏系统框架 → 遇到新问题无法快速组织答案

## 如何实现

### 难度分层（以 Checkpoint 为例）

| 面试官问法 | 难度 | 考察点 | 应该答什么 |
|-----------|------|--------|-----------|
| checkpoint 是什么？ | **初级** | 概念认知 | 定义 + 解决状态恢复 |
| checkpoint 解决什么问题？ | **初中级** | 场景理解 | 长任务、失败恢复、审批暂停 |
| checkpoint 怎么实现？ | **中级** | 工程落地 | 状态机 + DB 表 + task_id + current_node |
| checkpoint 存什么？存哪里？ | **中级** | 数据设计 | state、tool result、plan、approval、error；Redis/DB/对象存储 |
| checkpoint 和 event log 区别？ | **中高级** | 概念辨析 | 快照 vs 追加日志；当前状态 vs 历史过程 |
| 工具执行成功但 checkpoint 失败怎么办？ | **高级** | 可靠性 | 幂等、事务、action_id、补偿 |
| 如何支持任务回放？ | **高级** | 可观测 | event log + checkpoint + deterministic replay |
| checkpoint 在 Runtime 架构里是什么位置？ | **架构级** | 系统架构 | Durable execution / workflow state / runtime persistence |

### 通用答题框架

所有 Agent 工程化问题都可以套用这个 6 步结构：

```text
问题 → 机制 → 数据 → 流程 → 风险 → 项目

1. 问题：它解决 Agent 什么痛点和场景？
2. 机制：它的核心原理/架构设计是什么？
3. 数据：涉及哪些数据结构和存储设计？
4. 流程：执行流程/恢复流程怎么走？
5. 风险：生产环境有哪些坑？如何规避？
6. 项目：在我实际项目里怎么落地？
```

以 Checkpoint 为例：

```
1. 问题：Agent 长流程状态可靠性问题 → 中断恢复、审批暂停、审计
2. 机制：状态机 + Checkpoint 持久化 + Event Log
3. 数据：task 表、checkpoint 表、event 表、state JSON
4. 流程：执行前保存 → 执行后保存 → 失败保存 → 恢复时从 current_node 继续
5. 风险：重复执行（幂等）、一致性（事务）、状态过大（摘要+引用）、敏感信息脱敏
6. 项目：运维智能体分诊/采集/诊断/审批/执行/验证/RCA；应用生成 Router/Planner/Codegen/QA/Deploy
```

### Agent 生产化能力地图（6 大类别）

不要一个问题一个问题背，要按 Agent 生产化能力地图系统准备：

#### 1. Runtime 类（Agent 如何跑起来）

| 主题 | 高频问题 |
|------|---------|
| Agent Runtime | Runtime 是什么？和普通 API 有什么区别？ |
| State Machine | Agent 状态机怎么设计？ |
| Checkpoint | 如何断点续跑？ |
| Event Stream | 如何追踪执行过程？ |
| Task Queue | 长任务如何异步执行？ |
| Retry / Timeout | LLM 或工具超时怎么办？ |
| Cancellation | 用户取消任务怎么办？ |

#### 2. Tool 类（Agent 如何安全调用外部能力）

| 主题 | 高频问题 |
|------|---------|
| Tool Schema | 工具如何描述？ |
| Tool Executor | 工具如何执行？ |
| Permission | 工具权限怎么控制？ |
| Idempotency | 工具重复执行怎么办？ |
| Sandbox | 高风险动作如何隔离？ |
| Approval | 哪些动作需要人工确认？ |

#### 3. Planning 类（Agent 如何拆任务）

| 主题 | 高频问题 |
|------|---------|
| Router | 如何识别用户意图？ |
| Planner | 如何拆解任务？ |
| DAG | 任务之间依赖关系怎么表示？ |
| ReAct | Thought/Action/Observation 怎么理解？ |
| Multi-Agent | 多 Agent 如何协作？ |

#### 4. RAG / Memory 类（Agent 如何获得外部知识）

| 主题 | 高频问题 |
|------|---------|
| RAG | 为什么 Agent 需要 RAG？ |
| Embedding | 向量检索怎么用？ |
| Rerank | 检索结果如何排序？ |
| Memory | 长期记忆和短期记忆区别？ |

#### 5. Quality / Evaluation 类（如何保证 Agent 可靠）

| 主题 | 高频问题 |
|------|---------|
| Eval | Agent 怎么评测？ |
| Bad Case | Bad Case 怎么收集和归因？ |
| Metrics | 用哪些指标衡量效果？ |
| Replay | 如何离线回放评估？ |

#### 6. Safety / Governance 类（Agent 如何可控）

| 主题 | 高频问题 |
|------|---------|
| Guardrails | 如何限制模型输出？ |
| Permission | 谁能执行什么工具？ |
| Approval | 高风险动作如何审批？ |
| Audit | 如何审计 Agent 行为？ |

### 面试知识点准备模板（8 问法）

每个 Agent 面试知识点，都按这 8 个问题准备：

```text
1. 它是什么？
2. 它解决什么问题？
3. 它在 Agent 架构中处于哪一层？
4. 它如何实现？
5. 它存什么数据？
6. 它和相邻概念有什么区别？
7. 它在生产环境有什么坑？
8. 如何结合我的项目表达？
```

以 Checkpoint 为例：

```
1. 是状态快照机制
2. 解决长任务恢复问题
3. 属于 Agent Runtime / Workflow Engine 层
4. 通过状态机 + DB 持久化实现
5. 存 task、node、state、tool result、approval、error
6. 和 event log 区别是当前状态 vs 历史流水
7. 坑是重复执行、一致性、状态过大、敏感信息
8. 在运维智能体中用于分诊、采集、诊断、审批、验证、RCA
```

### 按项目优先级的准备策略

结合运维智能体和应用生成智能体两个项目，优先准备顺序：

**第一优先级：Agent Runtime** — 因为运维智能体最容易被问编排、失败恢复、断点续跑、人工审批、执行追踪。

**第二优先级：Router / Planner** — 因为应用生成智能体最容易被问意图识别、任务拆解、如何避免全量重生成。

**第三优先级：RAG / Memory** — 因为简历里写了场景化 RAG 和知识注入，容易被问 RAG 怎么影响 Router / Planner。

**第四优先级：Evaluation / Bad Case** — 因为 AI 岗非常爱问如何证明 Agent 有效、如何持续优化。

## 项目映射

- 运维智能体：Runtime 类问题是核心面试区，详见 [[25.6 高级面试关键词|25.6 面试关键词]]
- 应用生成智能体：Planning 和 RAG 类问题是核心面试区，详见 [[24-AI应用生成平台深水区/_index|24-应用生成]]
- 两个项目共享的 Checkpoint、Event Log、幂等等基础能力属于 Agent Runtime 层

## 高频追问

1. 面试官问 checkpoint，我怎么判断他想听哪个层级的答案？
2. 如果被问到没准备过的知识点，怎么套用答题框架？
3. 如何把 checkpoint 这类技术问题引向我的项目？

## 我的回答要点

> 遇到任何 Agent 面试题，先判断它属于 6 大类别中的哪一类（Runtime / Tool / Planning / RAG / Evaluation / Safety），再用 6 步框架组织答案（问题 → 机制 → 数据 → 流程 → 风险 → 项目）。答题时要从概念层递进到实现层再递进到生产可靠性层，体现你的工程化理解深度。最重要的是，每个知识点都要落到你的实际项目上——运维智能体怎么用 checkpoint、应用生成智能体怎么防重复执行——让面试官看到你不仅懂理论，更做过生产级 Agent 的工程化落地。
