# 13.5 任务生命周期

> 所属分支：[[13-Agent Runtime深水区✅/_index|13-Agent Runtime深水区]]

## 子节点 / 待填充要点
- AgentTask 生命周期状态
- run_status 枚举（COMPLETED / PARTIAL / DEGRADED / TIMEOUT / LLM_FAILED）
- 三级降级保护链
- 降级输出对下游的可见性

## 一句话定义

Agent 任务的完整生命周期从任务创建到正常完成、部分降级、超时或完全失败，每个状态都有明确的触发条件和对下游的可见输出格式。

## 解决什么问题

复杂 Agent 系统不能只有"成功"和"失败"两种状态。部分成功（2/5 个 Agent 超时）仍可提供有价值信息，需要精细的状态建模让下游节点根据任务状态做不同处理。

## 如何实现

### AgentTask 生命周期状态

```text
CREATED → QUEUED → RUNNING → ┬─ COMPLETED
                              ├─ PARTIAL (部分产出)
                              ├─ TIMEOUT (超时截断)
                              └─ LLM_FAILED (LLM 不可用)
```

### run_status 枚举定义

| 状态 | 含义 | 触发条件 | 下游处理 |
|------|------|---------|---------|
| `COMPLETED` | 正常完成 | ReAct 循环正常结束 | 正常纳入 aggregate |
| `PARTIAL` | 产出不完整 | 时间截断，部分产出 | conclusion 前缀为 `部分:`，权重 ×0.5 |
| `DEGRADED` | 降级输出 | LLM 超时或 JSON 解析失败，仍有 raw data | 使用规则兜底产出的 AnomalySignal |
| `TIMEOUT` | 超时 | 单 Agent 超时 | 返回空壳，不计入评分 |
| `LLM_FAILED` | LLM 不可用 | 所有 LLM 调用失败 | 返回规则兜底信号（如 K8s 仍能输出 CrashLoopBackOff） |

### 三级降级保护链

每一层降级都有明确的触发条件和输出格式：

| 层级 | 降级内容 | 触发条件 |
|------|---------|---------|
| **Agent 层** | L0→L1→L2→L3 | L0=正常、L1=JSON解析失败、L2=LLM超时有raw data、L3=完全失败 |
| **Fanout 层** | agent_tasks 为空 → fallback_from_plan() → 5 个默认 AgentTask | planner 未产出 agent_tasks |
| **整体** | 全部 Agent disabled → 自动 fallback 到 `_collect_one()` 原路径 | YAML 配置缺失 |

### 降级输出对下游的可见性

每个降级产物必须包含：
- `run_status`: 明确的状态枚举
- `degradation_level`: L0/L1/L2/L3
- `truncated`: 是否被时间截断
- `quality_score`: 降权后的质量评分

```python
# aggregate 根据 run_status 做差异化处理
if analysis.run_status == "PARTIAL":
    weight = 0.5
elif analysis.run_status in ("TIMEOUT", "LLM_FAILED"):
    weight = 0.0  # 不计入评分
else:
    weight = 1.0
```

### 最底层降级的兜底原则

即使所有 LLM 都失败，系统不抛异常、不崩溃。通过 `_extract_signals_by_rules()` 产出确定性规则信号（如检查 `containerStatuses.waiting.reason`），标记 `quality_score ≈ 0`，让上游知道"这是最低保障结果"。

## 项目映射

- OpsPilot SpecialistAgent：每个 Agent 内部 ReAct 循环有 4 层降级，fanout 层有 agent_tasks fallback，整体有回退到 v1 路径
- 降级信号通过 tracing event 记录 degradation_level，线上排障时可追溯

## 高频追问

1. Agent 部分失败了怎么办？是全部重来还是接受部分结果？
2. 降级后怎么保证下游节点不崩溃？
3. 怎么区分"LLM 失败"和"工具调用失败"？

## 我的回答要点

> Agent 任务生命周期不只是"成功/失败"二元状态。我们有 5 种 run_status：正常完成、部分产出、降级输出、超时、LLM 失败。每一层降级都有明确触发条件和输出格式，降级信号（degradation_level、truncated、quality_score）对下游可见。最底层保证不抛异常——通过确定性规则兜底（如检查 K8s containerStatuses）产出最低可用信号。降级设计的核心是"部分有用信息 > 没有信息"，而不是"全有或全无"。
