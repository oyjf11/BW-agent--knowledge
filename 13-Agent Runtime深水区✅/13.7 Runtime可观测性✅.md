# 13.7 Runtime可观测性

> 所属分支：[[13-Agent Runtime深水区✅/_index|13-Agent Runtime深水区]]

## 子节点 / 待填充要点
- Tracing span 层级设计
- AgentTracer API 使用
- 每个 Agent 的 LLM 调用和工具调用可见性
- 降级信号在 trace 中的记录
- 可观测性与信息过载的平衡

## 一句话定义

Agent Runtime 的可观测性通过层次化 Tracing span 实现：每个 Agent、每轮 ReAct、每次工具调用都有独立 span，降级信号作为 span event 记录，让线上排障可追溯。

## 解决什么问题

Agent 内部执行过程是黑盒——LLM 调用了几次？用了哪些工具？哪轮超时了？降级发生在哪一层？没有结构化 Tracing，排障只能靠日志 grep。

## 如何实现

### Span 层级设计

不改动 tracing 基础设施，通过现有 AgentTracer API 构建清晰的 span 层级：

```
fanout span (parent)
├── specialist.k8s_specialist           ← 每个 Agent 一个子 span
│   ├── react.round.0                   ← 每轮 ReAct
│   │   ├── tool.query_k8s_pods         ← gateway 自动继承 parent
│   │   └── tool.query_k8s_events
│   ├── react.round.1
│   │   └── tool.query_k8s_deployment_status
│   └── agent.final_analysis            ← event: degradation=L0, conf=0.85
├── specialist.db_specialist
│   ├── react.round.0
│   │   └── tool.query_slow_queries
│   └── agent.final_analysis
├── specialist.log_specialist
│   ...
├── specialist.metrics_specialist
│   ...
└── specialist.deployment_specialist
    ...
```

总计约 15-25 个 span（5 Agent × 平均 3-5 个 span），与现有 trace 粒度一致，不会造成信息过载。

### 降级信号的可观测记录

每个 Agent 的 final_analysis span 上打 event 记录：

```json
{
  "event": "agent.final_analysis",
  "degradation_level": "L0",
  "run_status": "COMPLETED",
  "confidence": 0.85,
  "truncated": false,
  "reagent_rounds": 2,
  "tools_called": ["query_k8s_pods", "query_k8s_events"]
}
```

降级时的 event 示例：

```json
{
  "event": "agent.final_analysis",
  "degradation_level": "L2",
  "run_status": "DEGRADED",
  "truncated": true,
  "reagent_rounds": 1,
  "quality_score": 0.3
}
```

### 可观测性设计原则

1. **不改动 tracing.py**：通过现有 AgentTracer API 构建 span，新增 Agent 不引入新的 tracing 依赖
2. **span 数量可控**：5 Agent × 3-5 span ≈ 15-25 span，不过载
3. **降级信号必记录**：所有 degradation_level、truncated、quality_score 作为 span event 记录
4. **通过 `/runs/{run_id}/trace` 查看**：每个 Agent 的每轮 LLM 调用和工具调用详情

## 项目映射

- OpsPilot Specialist Agent Pool：fanout → specialist.* → react.round.* → tool.* 四层 span 结构
- 降级信号通过 span event 记录 degradation_level 和 quality_score，线上排障可追溯每个 Agent 的有效性

## 高频追问

1. Agent 内部执行过程怎么看？怎么排查单个 Agent 的失败？
2. Tracing 会不会信息过载？怎么平衡粒度和可读性？
3. 降级发生在哪一层怎么发现？

## 我的回答要点

> Agent Runtime 的可观测性通过层次化 span 实现。fanout 是一个父 span，每个 Specialist Agent 一个子 span，每轮 ReAct 和每次工具调用都有下级 span。Agent 结束时打 event 记录 degradation_level、confidence、truncated 等关键状态。总共 15-25 个 span，既够用又不过载。关键是降级信号必须可见——没有 degradation_level 记录，线上排障就是盲的。
