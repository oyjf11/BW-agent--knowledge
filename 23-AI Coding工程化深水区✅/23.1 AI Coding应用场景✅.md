# 23.1 AI Coding应用场景

- AI 研发提效工具包

## 一句话定义
AI Coding 工程化不是简单用 AI 写代码，而是把需求、Spec、上下文、执行、验证、代码审查、CI/CD 和反馈迭代串成闭环，通过外层 Harness 让 AI 输出可控、可验证、可推广。

## 解决什么问题
单点 AI 写代码不可靠、不可验证、不可规模化。工程化落地需要标准化输入输出、可控执行边界、自动验证、失败反馈和质量度量。

## 如何实现

### 核心概念
| 概念 | 面试表达 |
|------|----------|
| Command | 用户触发的任务入口，如修 bug、生成测试、代码审查 |
| Agent | 执行某类任务的角色，如测试 Agent、Review Agent |
| Skill | 可复用能力包，如 Playwright 执行、接口校验、错误归因 |
| Rule | 执行约束，如不能改某些文件、必须跑哪些命令 |
| Spec | 需求和验收标准 |
| Runner | 执行命令、收集日志和测试结果 |

### 落地链路
```text
需求 / Issue → Spec 生成 → Agent 执行代码修改 → 本地 Runner 验证
  → 生成 MR → CI 执行 lint/test/build → AI Review
  → 人工合并 → 灰度发布 → 线上监控 → Bad Case 回流
```

### SDD / Spec Driven Development
```json
{
  "goal": "为客户列表增加导出功能",
  "scope": ["src/pages/customer-list.tsx"],
  "acceptance": [
    "列表页出现导出按钮",
    "点击后生成导出记录",
    "导出失败时展示错误提示"
  ],
  "constraints": ["不能修改登录模块", "不能新增未批准依赖"],
  "tests": ["Playwright 验证按钮可见", "模拟导出失败时展示 toast"]
}
```
