# 23.3 Harness Engineering

> 所属分支：[[23-AI Coding工程化深水区✅/_index|23-AI Coding工程化深水区]]

## 子节点 / 待填充要点
- Context Harness
- Tool Harness
- Execution Harness
- Test Harness
- Review Harness
- Eval Harness
- Audit Harness

## 一句话定义
Harness Engineering 是包在 AI 外面的一整套工程控制框架，不改变模型本身，但通过上下文管理、工具权限、执行记录、自动验证、失败重试、质量门禁和审计日志，让 AI 的输出可控、可验证、可回滚。

## 解决什么问题
模型生成不可控，直接调用模型存在安全、质量、审计风险。Harness 作为外层约束框架补足工程能力。

## 如何实现

### 七层 Harness 体系
| 层 | 做什么 |
|----|--------|
| Context Harness | 控制给模型什么上下文：代码索引、RAG、项目快照、规范库 |
| Tool Harness | 控制能调用什么工具：命令白名单、权限分级、操作审计 |
| Execution Harness | 控制命令怎么执行：容器隔离、超时控制、资源限制 |
| Test Harness | 自动跑 lint、tsc、test、build：失败收集日志、截图、trace |
| Review Harness | 代码审查、安全检查：规则 + AI Review 输出风险说明 |
| Eval Harness | 记录成功率、失败原因、ROI：持续评估 Agent 表现 |
| Audit Harness | 保存日志、diff、报告：操作可追溯、可审计 |

### 关键设计原则
- **模型只负责生成**，真正能落地靠外层 Harness
- 每层独立可插拔，不绑定模型
- 失败可追溯、可复现、可回滚
- 人工审核节点放在高风险操作前

## 项目映射
- 应用生成平台：Router → Planner → Codegen → QA 就是多层 Harness 的分工
- AI Coding 工具包：Context->Tool->Execution->Test->Review->Eval->Audit 全链路

## 我的回答要点
> Harness Engineering 可以理解为包在 AI 外面的一整套工程控制框架。它不改变模型本身，但通过上下文管理、工具权限、执行记录、自动验证、失败重试、质量门禁和审计日志，让 AI 的输出可控、可验证、可回滚。比如应用生成平台里的 Router→Planner→Codegen→QA 就是多层 Harness 的分工，每层做边界约束和质量校验。
