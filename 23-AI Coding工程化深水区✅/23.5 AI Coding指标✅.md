# 23.5 AI Coding指标

> 所属分支：[[23-AI Coding工程化深水区✅/_index|23-AI Coding工程化深水区]]

## 子节点 / 待填充要点
- 生成成功率
- 预览成功率
- 修改成功率
- 耗时
- Bad Case 沉淀
- ROI 衡量

## 一句话定义
通过定义和追踪 AI Coding 的核心指标（成功率、耗时、Bad Case），形成可量化的评估和改进闭环。

## 解决什么问题
没有指标就无法评估 AI Coding 的实际效果，也无法指导优化方向。指标是 Harness 的数据基础。

## 如何实现

### 核心指标
| 指标 | 定义 |
|------|------|
| 生成成功率 | 首次生成后通过所有质量门禁的比例 |
| 预览成功率 | 生成代码在 Sandpack 中可运行的比例 |
| 修改成功率 | 增量修改未被拒绝/通过验证的比例 |
| 平均耗时 | 从需求到可运行代码的时间 |
| Bad Case 数量 | 失败样本及原因分类 |
| ROI | 节省的开发工时 vs 平台成本 |

### Bad Case 运营
- 每次失败归因保存：失败原因、错误类型、修复方式
- 分类：模型输出错误 / Planner 规划错误 / Schema 约束错误 / 环境问题
- 反馈回 RAG 知识库避免重复错误

### Eval Harness 职责
Eval Harness 持续收集和评估 Agent 表现，包括成功率、失败原因、ROI 和 Bad Case，作为上一级 Harness 的量化输入。

## 项目映射
- 应用生成平台：每代任务记录 agent_runs、agent_steps、generation_artifacts、bad_cases
- 评估层：生成成功率、预览成功率、修改成功率、耗时、Bad Case

## 高频追问
1. 怎么评估 AI Coding 的效果？
2. 怎么衡量 AI Coding 的 ROI？
3. Bad Case 怎么回流和改进？

## 我的回答要点
> 没有指标就无法评估，也无法优化。我们会追踪首次生成通过率、预览可运行率、增量修改成功率、平均耗时和 Bad Case 分类。Bad Case 不光是记录失败，还要做原因分类、归因分析和知识回流，避免同类问题反复出现。ROI 的核心衡量是节省的开发时间 vs 平台成本 + 修复成本。
