### 核心关键词速查
| 关键词 | 一句话 |
|--------|--------|
| AI Coding 工程化 | 需求→Spec→执行→验证→审查→CI/CD→反馈的闭环 |
| Command | 用户触发入口，如修 bug、生成测试 |
| Agent | 执行某类任务的角色 |
| Skill | 可复用能力包 |
| Rule | 执行边界约束 |
| Spec | 可执行验收标准（含 goal、scope、acceptance、constraints、tests） |
| Runner | 执行 + 日志收集 + 结果反馈 |
| Harness | 七层控制框架（Context/Tool/Execution/Test/Review/Eval/Audit） |
| 质量门禁 | Lint→TSC→Test→Build→Review |
| Bad Case | 失败样本归因 + 知识回流 |

## 项目映射
- AI 研发提效工具包 + 应用生成平台 的双重映射路径

## 高频追问
- 面试官追问"你的 AI Coding 平台和 GitHub Copilot / Cursor 有什么区别？"时，强调你的工程化闭环（Spec→Execute→Verify→CI/CD→Bad Case），而不是单纯的代码补全。

## 我的回答要点
> AI Coding 工程化不是简单用 AI 写代码，而是把需求、Spec、上下文、执行、验证、代码审查、CI/CD 和反馈迭代串成闭环。模型只负责生成，真正能落地靠外层 Harness：包括上下文装配、工具边界、任务状态、自动测试、失败重试、质量门禁和 Bad Case 沉淀。
