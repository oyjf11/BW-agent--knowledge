# 24.1 核心链路

> 所属分支：[[24-AI应用生成平台深水区✅/_index|24-AI应用生成平台深水区]]

## 子节点 / 待填充要点
- 自然语言需求
- Router 意图识别
- UI Planner
- UI Codegen
- SQL 生成
- Supabase 建表
- CRUD 接入
- Sandpack 预览
- 打包部署

## 一句话定义
基于 LlamaCoder 二次改造的企业级 AI 轻应用生成平台，通过 Router → Planner → Codegen 多阶段生成流水线，将自然语言需求转化为可运行的 React + TypeScript + Tailwind 应用。

## 解决什么问题
原版 LlamaCoder 一次性 prompt 生成代码不可控，缺少企业级数据层、权限层和交付能力。多阶段拆分降低不确定性，补齐平台化能力。

## 如何实现
```text
用户自然语言需求
  ↓
前端提交生成任务 → 平台后端创建任务记录（MySQL）
  ↓
调用 Together AI SDK 流式返回生成内容
  ↓
Router 判断任务类型
  ↓
UIPlanner / SupabasePlanner / RoutingPlanner 分别规划页面、数据和路由
  ↓
Codegen 生成 React + TypeScript + Tailwind 代码
  ↓
生成 Schema / SQL → 在 PostgreSQL / Supabase 创建用户业务表
  ↓
企业 SSO 提供 user_id / tenant_id → Supabase JWT + RLS 做租户隔离
  ↓
Sandpack 预览、调试、保存版本、打包部署
```

## 项目映射
- 项目底座：基于 LlamaCoder 二次改造
- 模型调用：Together AI SDK
- 数据分层：MySQL 平台控制面 + PostgreSQL / Supabase 用户数据面
- 权限：企业 SSO + Supabase JWT + RLS 租户隔离

## 高频追问
1. 你们和原版 LlamaCoder 的区别是什么？
2. 为什么要拆多阶段生成，而不是一次性生成？
3. 平台数据为什么存 MySQL，用户数据为什么存 PG/Supabase？

## 我的回答要点
> 原版 LlamaCoder 更像验证"自然语言生成 React 应用"的交互闭环。我们真正做的是把它企业化：一方面把一次性代码生成拆成 Router、Planner、Codegen 多阶段，降低不可控风险；另一方面补齐数据层、权限层、版本层和交付层，让它从一个 Demo 工具变成企业内部轻应用生成平台。
