# 24.3 Planner深水区

> 所属分支：[[24-AI应用生成平台深水区✅/_index|24-AI应用生成平台深水区]]

## 子节点 / 待填充要点
- UIPlanner：页面结构、组件、交互
- SupabasePlanner：业务 Schema、表、字段、RLS、CRUD
- RoutingPlanner：路由、导航、页面路径
- Planner vs Router 区别
- target_files 与 allowed_changes

## 一句话定义
Planner 负责将 Router 判定出的任务意图转化为具体执行方案，输出 target_files、allowed_changes 和结构化执行计划。

## 解决什么问题
避免模型一次性生成不可控的结果。拆成 UI、数据、路由三个 Planner，各自专注于自己的领域，输入更小、输出更结构化。

## 如何实现
| 模块 | 职责 |
|------|------|
| UIPlanner | 规划页面结构、组件、交互 |
| SupabasePlanner | 规划业务 Schema、表、字段、RLS、CRUD |
| RoutingPlanner | 规划路由、导航、页面路径 |

```text
Router 输出 intent
  ↓
UIPlanner 提取字段和页面结构
  ↓
SupabasePlanner 生成业务 Schema
  ↓
RoutingPlanner 规划路由
  ↓
Codegen 执行生成
  ↓
QA 验证
```

## 项目映射
- 每个 Planner 输出 target_files 和 allowed_changes
- Codegen 只能在 Planner 限定的范围内修改代码

## 高频追问
1. 为什么 Planner 要拆成三个而不是一个？
2. Planner 和 Router 的区别是什么？
3. Planner 如何避免输出越界的修改方案？

## 我的回答要点
> Router 解决方向问题，Planner 解决路径问题。比如用户说"给客户列表加一个导出按钮，同时记录导出日志"，Router 判断这是 UI 修改加数据能力修改；UIPlanner 规划按钮放哪里，SupabasePlanner 规划是否要新增 export_logs 表，RoutingPlanner 判断是否影响路由，最后 Codegen 才生成代码。每个 Planner 输出 target_files 和 allowed_changes 作为 Codegen 的边界约束。
