# 24.4 生成稳定性

> 所属分支：[[24-AI应用生成平台深水区✅/_index|24-AI应用生成平台深水区]]

## 子节点 / 待填充要点
- 流式态 vs 预览态分离
- Sandpack 性能优化
- 长代码流式渲染优化
- Schema diff 增量修改
- 全量重写防避
- 依赖白名单与 shim

## 一句话定义
通过流式态与预览态分离、Schema diff 增量修改、依赖白名单等手段，保障 AI 生成应用在流式场景和长代码场景下的渲染稳定性和代码正确性。

## 解决什么问题
流式生成时每个 token 触发 Sandpack 编译会导致页面卡顿；AI 增量修改时容易全量重写项目；企业内网依赖不可达。

## 如何实现

### 流式渲染优化
| 问题 | 原因 | 解决 |
|------|------|------|
| 页面卡顿 | 每个 token 都 setState | buffer 批量刷新 |
| 代码高亮卡顿 | 长代码频繁重新高亮 | 延迟高亮 / 最终态高亮 |
| Sandpack 卡顿 | 每次代码变化都重新编译 | 流式态和预览态分离 |
| Preview 重建 | 组件卸载重挂载 | 隐藏代替卸载 |
| 内网依赖慢 | CDN / 外部依赖不可达 | 依赖白名单、本地化、shim |
| 大文件渲染慢 | React render 频繁 | useRef 缓存、虚拟化、分片更新 |

### 增量修改防全量重写
- 保存 project snapshot：文件树、路由、Schema 快照
- 保存页面元数据、路由元数据、Schema 版本
- Planner 输出 target_files，Codegen 只能改目标文件
- Git diff / 文件白名单检查
- 增量修改前对比新旧 Schema

## 项目映射
> 把"流式生成态"和"可运行预览态"分开。模型生成时先轻量展示代码，不实时推给 Sandpack 编译。等代码块完整后，或者用户点击 Run，再提交给 Sandpack。

## 高频追问
1. 流式代码生成为什么会卡？怎么优化？
2. 怎么避免 AI 每次全量重写项目？
3. Sandpack 在企业内网环境下有什么坑？

## 我的回答要点
> 把"流式生成态"和"可运行预览态"分开，避免每个 token 都触发打包和预览重建。增量修改时先判断影响范围，只把相关页面、表结构和路由信息给模型，Planner 输出 target_files 和 allowed_changes，Codegen 只能在这个范围内修改。
