# 24.6 高级面试关键词

> 所属分支：[[24-AI应用生成平台深水区✅/_index|24-AI应用生成平台深水区]]

## 子节点 / 待填充要点
- 25 个高频面试题（应用生成平台方向）
- 核心话术
- 避坑提醒

## 一句话定义
应用生成平台方向最可能被追问的面试题集合及回答要点速查。

## 解决什么问题
快速检索高频面试题的标准回答口径，避免临场表述混乱。

## 如何实现

### 应用生成平台方向高频 15 问
1. 你们为什么基于 LlamaCoder 改，而不是自研？
2. 原版 LlamaCoder 和你们改造后的平台有什么区别？
3. Together AI SDK 在系统里负责什么？
4. 你们的 runnable 是什么？和 LangChain Runnable 是一回事吗？
5. 前端怎么处理模型流式返回？
6. 为什么 Sandpack 在流式生成场景会卡？
7. 你们怎么优化长代码流式渲染？
8. Router、UIPlanner、SupabasePlanner、RoutingPlanner 分别负责什么？
9. Router 和 Planner 的区别是什么？
10. 为什么要拆多阶段生成，而不是一次性生成？
11. 平台数据为什么存 MySQL？
12. 用户业务数据为什么存 PostgreSQL / Supabase？
13. MySQL 和 Supabase 之间如何关联？
14. 企业 SSO 和 Supabase RLS 怎么打通？
15. tenant_id 从哪里来？如何保证可信？
16. RLS 的 `using` 和 `with check` 有什么区别？
17. 动态建表怎么保证安全？
18. 新旧 Schema 如何 diff 和迁移？
19. 如何避免 AI 每次全量重写项目？

## 项目映射
> 核心口径：我们基于 LlamaCoder 和 Together AI SDK 做了企业级 AI 轻应用生成平台，把原来 prompt 生成 React 小应用的 Demo 能力，扩展成 Router / Planner 多阶段生成、Schema / SQL 自动建表、MySQL 平台控制面、PG / Supabase 业务数据面、SSO 鉴权、Supabase RLS 租户隔离、Sandpack 预览调试和版本化交付闭环。

## 高频追问
- 如果面试官连续追问 3 个以上技术细节时，按「问题定义 → 方案对比 → 我的选择 → 实现细节 → 验证方式」的结构回答。

## 我的回答要点
> 回答原则：先讲架构分层（控制面/数据面），再讲关键链路（Router→Planner→Codegen），最后讲安全边界（SSO→JWT→RLS）。避免只说"我们在原版上加了些功能"，而是说"我们把 Demo 工具改造成企业平台"。
