# 25.1 核心链路

> 所属分支：[[25-运维智能体-AIOps深水区✅/_index|25-运维智能体-AIOps深水区]]

## 子节点 / 待填充要点
- 工单接入
- 自动分诊
- 服务识别
- 多源证据采集
- 根因假设
- 处置建议
- 人工审批
- 执行验证
- RCA 复盘

## 一句话定义
AI 运维智能体的核心处理链路：从工单/告警接入到根因分析、处置建议、人工审批、执行验证和 RCA 复盘的全流程。

## 解决什么问题
传统运维依赖人工排查，响应慢、经验不可复用。Agent 通过自动分诊、证据采集和根因假设加速故障定位，同时通过人审批保证安全。

## 如何实现

### 核心链路
```text
工单/告警接入 → 自动分诊 → 服务识别 → 多源证据采集
  → 根因假设（按概率排序） → 处置建议
  → 人工审批 → 执行验证 → RCA 复盘
```

### 运维 Agent vs 应用生成 Agent
| 对比 | 应用生成 Agent | 运维 Agent |
|------|--------------|-----------|
| 目标 | 生成应用 | 诊断和处置故障 |
| 输入 | 自然语言需求 | 工单、告警、日志 |
| 核心链路 | Router → Planner → Codegen → QA | 分诊 → 证据 → 诊断 → 审批 → 执行 → RCA |
| 风险 | 生成错误代码 | 误操作生产 |
| 安全重点 | 权限、数据隔离、代码验证 | 人审、只读优先、模拟执行、回滚 |
| 产物 | 应用、代码、Schema | 根因、处置建议、RCA |

### 为什么不能全自动
运维场景涉及生产系统，错误动作可能造成事故。Agent 可以做证据收集、根因假设、处置建议，但重启、扩容、回滚、删除、配置变更这类写操作必须人工审批。

## 项目映射
- OpsPilot 全链路实现：只读证据优先 → 写操作人工审批 → 受控执行 → 结果验证

## 高频追问
1. 运维智能体和应用生成智能体的架构有什么不同？
2. 运维 Agent 为什么不能全自动执行？
3. 证据采集怎么做？怎么保证证据可信？

## 我的回答要点
> 应用生成智能体偏创造型任务，重点是生成正确应用；运维智能体偏诊断和决策任务，重点是证据链、安全边界和人审。两者都需要 Agent Workflow、Checkpoint 和日志审计，但风险控制重点不同。运维 Agent 的安全设计核心：只读优先 → 建议生成 → 人工审批 → 受控执行 → 验证 → RCA。
