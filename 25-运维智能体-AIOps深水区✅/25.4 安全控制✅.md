# 25.4 安全控制

> 所属分支：[[25-运维智能体-AIOps深水区✅/_index|25-运维智能体-AIOps深水区]]

## 子节点 / 待填充要点
- 为什么运维 Agent 不能全自动
- 只读优先原则
- 人审批流程
- 模拟执行
- 受控执行
- 回滚机制

## 一句话定义
运维 Agent 因涉及生产系统，错误动作可能造成事故，必须设计分层安全控制：只读证据优先 → 模拟执行 → 人工审批 → 受控执行 → 结果验证。

## 解决什么问题
AI 诊断可能出错，自动执行写操作风险不可接受。需要安全控制保证 Agent 不越权、不误操作。

## 如何实现

### 安全控制链
```text
证据收集（只读）→ 根因假设 → 处置建议生成
  ↓
人工审批（写操作必须）
  ↓
模拟执行（sandbox 预演）
  ↓
受控执行（限制资源、超时、可回滚）
  ↓
结果验证
  ↓
RCA 复盘 + 知识沉淀
```

### 关键安全原则
- **只读优先**：Agent 先做证据收集、根因假设、处置建议，不做变更
- **写操作需人工审批**：重启、扩容、回滚、删除、配置变更
- **模拟执行**：高风险操作先在 sandbox 验证
- **受控执行**：限制资源、超时保护、异常回滚
- **变更记录**：所有操作落审计日志

### 运维 Agent vs 应用生成 Agent 风险对比
| 对比 | 应用生成 Agent | 运维 Agent |
|------|--------------|-----------|
| 目标 | 生成应用 | 诊断和处置故障 |
| 输入 | 自然语言需求 | 工单、告警、日志 |
| 核心链路 | Router → Planner → Codegen → QA | 分诊 → 证据 → 诊断 → 审批 → 执行 → RCA |
| 风险 | 生成错误代码 | 误操作生产 |
| 安全重点 | 权限、数据隔离、代码验证 | 人审、只读优先、模拟执行、回滚 |
| 产物 | 应用、代码、Schema | 根因、处置建议、RCA |

## 项目映射
- OpsPilot：工单接入 → 自动分诊 → 多源证据采集 → 根因假设 → 处置建议 → 人工审批 → 执行验证 → RCA 复盘

## 高频追问
1. 运维 Agent 为什么不能全自动执行？
2. 如果 Agent 诊断错了怎么办？
3. 人审批的粒度怎么设计？

## 我的回答要点
> 运维场景涉及生产系统，错误动作可能造成事故。Agent 可以做证据收集、根因假设、处置建议，但重启、扩容、回滚、删除、配置变更这类动作必须人工审批。我们的设计是只读证据优先，写操作走建议生成 → 人工确认 → 模拟执行 → 受控执行 → 结果验证 → RCA 的安全链路。
