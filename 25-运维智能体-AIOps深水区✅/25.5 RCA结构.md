# 25.5 RCA结构

> 所属分支：[[25-运维智能体-AIOps深水区✅/_index|25-运维智能体-AIOps深水区]]

## 子节点 / 待填充要点
- RCA 报告结构
- RCA Writer Agent 职责
- RCA 的输入来源
- 历史 RCA 如何被复用
- RCA 与知识沉淀

## 一句话定义
RCA（Root Cause Analysis）复盘报告由 RCA Writer Agent 基于全链路记录（工单、分诊、证据、诊断、审批、执行、验证）自动生成，结构化的 RCA 沉淀为历史案例，供未来诊断复用。

## 解决什么问题
手动写 RCA 耗时且容易遗漏关键细节。自动化 RCA 保证每次故障都有结构化的复盘记录，并且可被未来诊断引用。

## 如何实现

### RCA 生成流程

```text
Verifier Agent 验证恢复
   ↓
RCA Writer Agent 读取全链路数据：
  - tickets（工单原始信息）
  - evidence_items（采集到的证据）
  - diagnosis_results（根因假设、置信度）
  - remediation_plans（修复方案、回滚方案）
  - approvals（审批记录）
  - execution_records（执行动作、结果）
  - verification_results（验证结果）
   ↓
生成结构化 RCA 报告
   ↓
存入 rca_reports 表 + historical_rcas（案例库）
```

### 历史 RCA 的复用路径

| 复用场景 | 方式 |
|---------|------|
| 新故障诊断 | Diagnosis Agent 查询 historical_rcas 表，匹配相似故障模式 |
| 告警降噪 | 已知故障模式的告警降低优先级 |
| SOP 更新 | 从 RCA 中提取最佳处置路径更新 runbooks |
| 回归预防 | improvement_actions 自动生成待办并追踪闭环 |

### 数据库设计

| 表 | 存什么 |
|---|---|
| `rca_reports` | RCA 报告完整内容 |
| `historical_rcas` | 历史复盘案例（用于检索和匹配） |
| `lessons_learned` | 经验教训（独立表，可检索） |
| `improvement_items` | 改进项（可追踪闭环状态） |

## 项目映射
- OpsPilot 端到端闭环中包含 RCA 复盘环节
- RCA 结构化沉淀为知识库，支撑新故障的快速诊断

## 高频追问
1. RCA 是自动生成的还是人工编写的？
2. 历史 RCA 怎么被新故障诊断复用？
3. 怎么保证 RCA 的质量？

## 我的回答要点
> RCA 由 RCA Writer Agent 基于全链路记录自动生成结构化报告，包含时间线、根因、影响范围、处置过程、经验教训和改进措施。RCA 沉淀后存入 historical_rcas 表，Diagnosis Agent 在新故障诊断时会检索历史案例匹配相似故障模式。improvement_actions 自动生成待办并追踪闭环。核心不是自动化写报告本身，而是把复盘知识结构化，让每次故障都能为下一次诊断提供参考。
