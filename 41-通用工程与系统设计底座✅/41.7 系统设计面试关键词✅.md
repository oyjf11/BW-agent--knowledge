# 41.7 系统设计面试关键词

> 所属分支：[[41-通用工程与系统设计底座✅/_index|41-通用工程与系统设计底座]]

## 子节点 / 待填充要点
- 设计企业 AI Coding 平台（八层架构）
- 设计企业轻应用生成平台（九层架构）
- 设计运维智能体平台

## 一句话定义
系统设计面试题的标准回答框架：按分层架构（入口→编排→执行→数据→安全→评估）展开，每层明确职责和技术选型。

## 解决什么问题
面试官给一个开放式系统设计题，需要快速组织分层架构回答。

## 如何实现

### 系统设计题 1：企业 AI Coding 平台（八层）
```text
1. 用户入口：IDE 插件 / CLI / Web / IM

2. 任务层：Issue / Spec / Command / Agent Run

3. 编排层：Router / Planner / Executor / QA

4. 上下文层：代码索引 / RAG / 项目快照 / 规范库

5. 执行层：文件修改 / 命令执行 / 测试 / 构建 / MR

6. 数据层：MySQL 控制面 / Redis 队列 / 对象存储 / 向量库

7. 安全层：权限 / 沙箱 / 审批 / 审计 / 租户隔离

8. 评估层：成功率 / 失败原因 / ROI / Bad Case
```

### 系统设计题 2：企业轻应用生成平台（九层）
```text
1. 输入层：自然语言需求、模板选择、业务场景

2. 生成编排层：Router、UIPlanner、DataPlanner、RoutingPlanner、Codegen

3. 模型层：Together AI SDK、模型选择、Prompt 模板、流式返回

4. 平台数据层：MySQL（应用、页面、版本、任务、审计）

5. 用户业务数据层：PG/Supabase（业务表、业务数据、RLS）

6. 权限层：企业 SSO、user_id、tenant_id、Supabase JWT

7. 预览层：Sandpack、错误反馈、调试面板

8. 发布层：打包、部署、版本管理、回滚

9. 评估层：生成成功率、预览成功率、修改成功率、耗时、Bad Case
```

### 系统设计题 3：运维智能体平台
```text
1. 告警/工单接入层：监控系统、工单平台

2. 分诊层：故障类型、影响范围、紧急程度判定

3. 证据采集层：日志、指标、trace、配置、变更记录

4. 诊断层：根因假设生成、概率排序

5. 处置层：修复建议生成、风险评估

6. 审批层：人工审批工作流（写操作）

7. 执行层：模拟执行、受控执行、回滚

8. 复盘层：RCA 报告、知识沉淀

9. 安全层：只读优先、人审、权限、审计
```

## 项目映射
- 三层设计均可复用 Router/Planner 模式、Harness 体系、数据控制面/数据面分离

## 高频追问
1. 设计一个企业 AI Coding 平台
2. 设计一个企业轻应用生成平台
3. 设计一个运维智能体

## 我的回答要点
> 回答系统设计题时，按分层展开（入口→编排→执行→数据→安全→评估），每层一句话定义职责 + 技术选型。不要跳着讲，按"用户从哪来，数据怎么流，安全怎么做，效果怎么评估"的顺序。最后主动抛一个关键取舍点引导面试官追问。
